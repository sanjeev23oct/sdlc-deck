Example: Satsang Cards

What the spec actually says

.kiro/specs/satsang-cards/12-bulk-visit-approval/requirements.md

Acceptance criteria

  • "The page SHALL be protected: unauthenticated users are redirected to login."
  • "The endpoint SHALL create each enrollment with card_status_id = APPROVED."

Edge cases

  • "If the card number is not found the page SHALL show an inline error: Card not found."
  • "If no previous (CLOSED) visit exists ... return an empty list (not an error)."

Correctness properties

  • "No duplicates: the same (satsang_visit_id, satsang_card_id) pair is never inserted twice."

Open questions

  • "Should blocked cards be silently skipped server-side or surfaced as per-card errors?"
