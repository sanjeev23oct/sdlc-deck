Principles

Five principles behind our SDLC

1Every task has a skillEach task names its maker skill and how it gets checked. No skill, no run.
2Maker and checker are separateThe checker runs in a fresh context and sees only the task and the files. Done is its call.
3Evidence before claimsNothing is done because a model says so. The checker runs the check, and the evidence is the audit trail.
4Consistency is engineeredThe how lives in versioned skills and the what in tasks.md, so the same type of task runs the same way.
5The loop learnsEvery run ends with a retrospective, and gaps get fixed in the skill.
