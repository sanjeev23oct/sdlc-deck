ONE CYCLE, RUN BY loop-run

  1. Gate: the task names a skill and a checker, and its dependencies are done.
  2. Make: the maker skill implements the task. It does not mark it done.
  3. Check: a fresh sub-agent reads the Goal and the files, then runs the Evidence command.
  4. Pass: write the evidence file, log the step, move to the next task.
  5. Fail: return the findings to the maker, within the task’s budget.
  6. Learn: retrospective records skill-gap or agent-slip, plus PATTERN OBSERVED notes.
A checker that can read the maker’s reasoning is a rubber stamp. One that can only read the code and run the command is a control.
